## Introduction

A team keeps its assets in a repository of its own and builds them with `@chassis-ui/assets`, the package behind this build. `chassis-assets init` writes the baseline of such a repository: the configuration, the Git LFS rules, a README, and the workflows that check every push and release every tag. This page takes you from an empty folder to a first release.

## Prerequisites

- **Node.js** 22.12 or later.
- **Git** and **Git LFS**, from [git-lfs.com](https://git-lfs.com). Fonts and raster images are Git LFS files.
- **npm** or **pnpm**. The baseline names one of them in its README and its workflows.

## Create the repository

Run `init` with the package, in the folder the repository will be:

```bash
mkdir acme-assets && cd acme-assets
npx @chassis-ui/assets init --brand acme --app docs:web --app mobile:ios,android
```

Each `--app` is a name and its platforms, `web`, `ios` or `android`, separated by commas. Without options the repository has one brand, `main`, and one app, `site`, on the web. The command writes nine files and prints them:

```
package.json                              The brands, the apps and the scripts
chassis.checks.json                       The files that consumers read by name, none yet
.gitattributes                            The Git LFS rules of the fonts and the images
.gitignore                                dist/, archives/, node_modules/
.nvmrc                                    The Node.js version of the workflows
README.md                                 The layout and the commands
.github/workflows/ci.yml                  Lint, build and verify on every push
.github/workflows/release.yml             Build, verify and archive on every tag
source/_default/_shared/other/readme.txt  A stand-in for the first asset
```

It writes nothing when one of them exists; `--force` writes over the files that exist, and `--dry-run` prints them without writing. `--name` sets the package name, by default the name of the folder, and `--pm pnpm` makes the README and the workflows use pnpm.

Then make it a repository, and install the package:

```bash
git init && git lfs install
npm install
npm run build
```

The build writes `dist/<platform>/<app>/<brand>/` for each job, with the stand-in file. `npm run verify` checks it, and passes.

## Add the first files

The assets go in `source/<brand>/<app>/<type>/`: `fonts/`, `images/`, `icons/`, or any folder name of your own. The files every brand gets go under `source/_default/`, the files every app of a brand gets under `source/<brand>/_shared/`, and a brand file replaces the default file of the same path. The [design guidelines]([[docsref:/getting-started/design-guidelines]]) give the naming rules, and the [asset type pages]([[docsref:/asset-types/fonts]]) say what each type holds.

Once a brand or an app has a file of its own, delete `source/_default/_shared/other/readme.txt`: it only stood in for the first build. Then run the checks:

```bash
npm run lint
npm run build
npm run verify
```

`lint` checks the names and the layout of `source/`, and `verify` the output against the source. Both run in CI on every push to `main` and on every pull request.

## Name what consumers read

When an app or a site reads a file of the output by name, add it to `chassis.checks.json`, by job, with who reads it:

```json
{
  "contracts": {
    "web/docs/acme": [
      {
        "reader": "the layout of the documentation site",
        "files": ["images/site-logo.svg", "fonts/fonts.css"]
      }
    ]
  }
}
```

`verify` then fails when a build no longer has the file, before a consumer does. The [build system]([[docsref:/getting-started/build-system]]#contracts) page describes the forms an entry takes.

## Release a version

A release is a tag with the version of `package.json`:

```bash
git tag v0.1.0
git push origin main v0.1.0
```

The release workflow builds and verifies every job, writes one `acme-assets-<platform>-<app>-<brand>-0.1.0.zip` per job with `chassis-assets archive`, and creates the GitHub release with them attached. A tag that is not the version of `package.json` fails the workflow. An app takes the archive of its platform, app and brand from the release; the [use in project]([[docsref:/use-in-project/web-applications]]) pages say what to do with it on each platform.

A project can also add the repository as a Git submodule and build it there with `npx chassis-assets build --cwd vendor/assets --out static/assets`: the repository needs nothing installed, the project installs the package.

## Change the baseline

Everything `init` writes is yours to change. The workflows call the scripts of `package.json`, so a script can take options, such as `chassis-assets build --optimize` with `sharp` and `svgo` installed. The [build system]([[docsref:/getting-started/build-system]]) page lists every command and option.
