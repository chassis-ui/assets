## Introduction

The Android output of a brand and an app is the folder `dist/android/<app>/<brand>/`. The build copies the files of `source/` into it, renames them to snake_case, and sorts the images into density folders. The samples use the configuration of the [quick start]([[docsref:/getting-started/quick-start]]): the Android app is `mobile` and the brands are `acme` and `globex`; your own configuration has other names in the same places. The file names of the samples, such as `hero_banner.png`, are examples: your output has the files of your source, under the names of the table below.

```text
dist/android/<app>/<brand>/
├── fonts/
│   ├── ui_license.txt
│   ├── ui_normal.ttf
│   └── ...
├── images/
│   ├── drawable/
│   │   └── hero_banner.png
│   └── drawable-xhdpi/
│       └── hero_banner.png
└── icons/
    ├── ic_arrow_right_solid.svg
    └── ...
```

<CxTable>
| Type | What Android gets | Names |
| --- | --- | --- |
| Fonts | TTF and OTF files, and the license of each font | snake_case |
| Images | Every format, in density folders | snake_case, indicator removed |
| Icons | SVG files only | snake_case with the `ic_` prefix |
| Any other folder | Every file | snake_case |
</CxTable>

<Callout type="warning">
The default output is not a `res/` folder. The build keeps the subfolders of `images/`, which `res/` does not allow, and it copies an SVG as SVG, which `res/` does not accept. You copy the files you need into `res/`, or build with `--res`, see [Res folder](#res-folder). For the icons, build with `--vector-drawables` or import the SVG files with Android Studio, see [Vector drawables](#vector-drawables).
</Callout>

## Installation

An app gets the files in one of three ways: from a release archive, from a Git submodule that it builds, or from a build in a clone. The samples of this page read the output from `vendor/assets/dist/android/mobile/`, with the repository of assets in the folder `vendor/assets/` of the Android project.

### Release archive

A release archive holds the output of one platform, one app and one brand, and needs neither Node.js nor Git LFS. Each GitHub release of a repository of assets has one archive per job attached, named `<name>-<platform>-<app>-<brand>-<version>.zip` after the name and the version of its `package.json`. The archive holds the content of `dist/<platform>/<app>/<brand>/` at its top level, so unpack it into a folder named after the brand:

```bash
mkdir -p assets-dist/acme
unzip "acme-assets-android-mobile-acme-<version>.zip" -d assets-dist/acme
```

### Git submodule

A submodule pins the app to one commit of the assets and lets the app build them itself. You need Node.js 22.12 or later and Git LFS, which holds the fonts and the raster images. A Gradle project has no `package.json`, so the package `@chassis-ui/assets` is installed in the submodule, whose `package.json` lists it and which brings nothing else. The address is an example; use the one of your repository of assets:

```bash
git lfs install
git submodule add https://github.com/acme/acme-assets.git vendor/assets
cd vendor/assets
git lfs pull
npm install
npx chassis-assets build --platform android                              # every brand and app of the platform
npx chassis-assets build --platform android --brand acme --app mobile    # one job
```

### Build from a clone

A clone in the same folder works the same way, and suits a team that changes the assets and the app together but keeps them in separate histories: run `git clone https://github.com/acme/acme-assets.git vendor/assets` in place of `git submodule add`, then the same commands.

A build with a filter keeps the rest of `dist/`; add `--clean` to remove the folders of the selected jobs first. See the [build system page]([[docsref:/getting-started/build-system]]) for every option.

## Output layout

The job folder holds one folder per type of the app. The build writes `fonts/` flat, puts `drawable/` and the density folders under `images/` and under each of its subfolders, and keeps the subfolders of `icons/`. For a source with two font roles, a few images and a few icons, the build writes:

```text
dist/android/<app>/<brand>/
├── fonts/
│   ├── code_license.txt
│   ├── code_normal.ttf
│   ├── ui_license.txt
│   ├── ui_normal.ttf
│   ├── ui_normal_italic.ttf
│   └── ui_strong.ttf
├── icons/
│   ├── ic_arrow_right_outline.svg
│   ├── ic_arrow_right_solid.svg
│   └── ...
└── images/
    ├── drawable/
    │   └── hero_banner.png
    ├── drawable-xhdpi/
    │   └── hero_banner.png
    ├── drawable-xxhdpi/
    │   └── hero_banner.png
    ├── logo/
    │   └── drawable/
    │       ├── wordmark.png
    │       └── wordmark.svg
    └── onboarding/
        ├── drawable/
        │   ├── welcome_dark.png
        │   └── welcome_light.png
        └── drawable-xhdpi/
            ├── welcome_dark.png
            └── welcome_light.png
```

A file of `source/<brand>/<app>/<type>/` or `source/_default/<app>/<type>/`, or of the `_shared/<type>/` folder of either brand, is under `<type>/` of the job, in the same subfolders, with its name in snake_case, so a path is the same in every brand that has the file. To find the name of a file, list the output of the job: `find dist/android/mobile/acme -name 'hero_banner*'`.

### Res folder

The build writes a `res/` folder itself when you give it the `--res` option. Add `--vector-drawables`, which needs the package `svg2vectordrawable`, to get the icons into it:

```bash
cd vendor/assets
npm install svg2vectordrawable
npx chassis-assets build --platform android --res --vector-drawables
```

The font files, the raster images and the vector drawables move into `res/`, without the subfolders they had:

```text
dist/android/<app>/<brand>/
├── fonts/
│   ├── code_license.txt
│   └── ui_license.txt
├── images/
│   └── logo/
│       └── drawable/
│           └── wordmark.svg
└── res/
    ├── drawable/
    │   ├── hero_banner.png
    │   ├── ic_arrow_right_outline.xml
    │   ├── ic_arrow_right_solid.xml
    │   └── welcome.png
    ├── drawable-night/
    │   └── welcome.png
    ├── drawable-night-xhdpi/
    │   └── welcome.png
    ├── drawable-nodpi/
    │   └── wordmark.png
    ├── drawable-xhdpi/
    │   ├── hero_banner.png
    │   └── welcome.png
    ├── drawable-xxhdpi/
    │   └── hero_banner.png
    └── font/
        ├── code_normal.ttf
        ├── ui_normal.ttf
        ├── ui_normal_italic.ttf
        └── ui_strong.ttf
```

Copy the folder into the source set of the brand, and the licenses beside it:

```bash
BRAND=acme
ASSETS="vendor/assets/dist/android/mobile/$BRAND"

mkdir -p "app/src/$BRAND/assets/licenses"
cp -R "$ASSETS/res" "app/src/$BRAND/"
cp "$ASSETS"/fonts/*_license.txt "app/src/$BRAND/assets/licenses/"
```

A pair `welcome_light` and `welcome_dark` of one folder is the resource `welcome`, see [Night images](#night-images). An image of one size goes to `drawable-nodpi/`, which Android draws without scaling, see [Density folders](#density-folders). A name that both a pair and another image ask for fails the build, as the app would show the wrong image in one mode.

What `res/` does not take stays in its folder, and the build warns about the number of such files: the licenses, the SVG images, and without `--vector-drawables` every icon. When two subfolders of `images/` hold an image of one name, the folder nearest to `images/` gets the resource and the other file stays. The release archives are built without the option, and the rest of this page describes the default output.

### Copying to res

Without the option, a copy script moves the files that `res/` accepts as they are: the font files and the PNG and WebP images. It lists the folders of `images/` that the app uses, because `res/` has one `drawable/` folder and the output has one per subfolder. Add this script to the Android project as `scripts/sync-assets.sh`:

```bash
#!/bin/bash
# scripts/sync-assets.sh <brand>
set -euo pipefail

BRAND="${1:-acme}"
ASSETS="${ASSETS_ROOT:-vendor/assets/dist/android/mobile}/$BRAND"
SRC="app/src/$BRAND"

# Fonts go to res/font/, their licenses to assets/licenses/
mkdir -p "$SRC/res/font" "$SRC/assets/licenses"
find "$ASSETS/fonts" -maxdepth 1 \( -name '*.ttf' -o -name '*.otf' \) -exec cp {} "$SRC/res/font/" \;
cp "$ASSETS"/fonts/*_license.txt "$SRC/assets/licenses/"

# The PNG and WebP files of each folder of images/ that the app uses
for folder in images images/onboarding; do
  for density in "$ASSETS/$folder"/drawable*/; do
    target="$SRC/res/$(basename "$density")"
    mkdir -p "$target"
    find "$density" -maxdepth 1 \( -name '*.png' -o -name '*.webp' \) -exec cp {} "$target/" \;
  done
done
```

The script writes to the source set of the brand, `app/src/<brand>/`, which [Brand switching](#brand-switching) uses; an app with one brand sets `SRC` to `app/src/main`. With release archives, set `ASSETS_ROOT` to the folder that holds the unpacked brands:

```bash
./scripts/sync-assets.sh acme                                 # from vendor/assets/dist/
ASSETS_ROOT=assets-dist ./scripts/sync-assets.sh acme          # from an unpacked archive
```

When two listed folders hold a PNG of the same name in the same density folder, the folder listed last wins.

The script copies and replaces files and never removes one. A file that a later build does not write again stays in `app/src/<brand>/res/`: an image that was renamed, or the PNG of an image that a build with `--webp` now writes as WebP. Delete such a file by hand, see [Duplicate resources](#duplicate-resources).

## Fonts

The build gives Android the TTF and OTF files of `fonts/` and the `<role>-license.txt` of each font, renamed to snake_case. A font file is named after its role and its style, `ui_normal.ttf` or `ui_strong_italic.ttf`, so two brands with different typefaces have the same file names. See [Fonts]([[docsref:/asset-types/fonts#platform-output]]) for the roles and the source layout.

### Font resources

The copy script puts the font files in `res/font/`, where each one becomes a resource named after the file: `R.font.ui_normal`. The licenses go to `assets/licenses/`, because `res/font/` accepts only font files and XML, and the app still has to ship the license with the font.

### Font families

A font family resource groups the files of one role, so a layout asks for the role and a weight. Add `res/font/ui.xml` with one entry for each file the app uses:

```xml
<?xml version="1.0" encoding="utf-8"?>
<font-family xmlns:android="http://schemas.android.com/apk/res/android">
    <font android:font="@font/ui_normal" android:fontStyle="normal" android:fontWeight="400" />
    <font android:font="@font/ui_normal_italic" android:fontStyle="italic" android:fontWeight="400" />
    <font android:font="@font/ui_strong" android:fontStyle="normal" android:fontWeight="600" />
    <font android:font="@font/ui_strong_italic" android:fontStyle="italic" android:fontWeight="600" />
</font-family>
```

The file name does not hold the weight. `normal` and `strong` are names of [Chassis Tokens](https://chassis-ui.com/tokens/), and the number behind each one is a choice of the brand: the `400` and `600` above are examples, so take the numbers from the tokens of your brand. The attribute needs a literal number, so a brand with other weights needs its own `ui.xml` in `app/src/<brand>/res/font/`.

The attributes are in the `android:` namespace, which every view reads from API 26 on. A family that has only `app:` attributes, the namespace of AndroidX, loads in an `AppCompatTextView` and not in a plain `TextView` or any other view of the framework: the text shows in the system font, without an error. An app that supports API 25 or lower repeats each attribute with `app:` beside the `android:` one.

### Using a font

A view takes the family by its resource name, and Jetpack Compose builds a `FontFamily` from the same files. Use the family in a layout:

```xml
<TextView
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:fontFamily="@font/ui"
    android:text="@string/title" />
```

Use the files in Jetpack Compose:

```kotlin
val UiFamily = FontFamily(
    Font(R.font.ui_normal, FontWeight.Normal),
    Font(R.font.ui_normal_italic, FontWeight.Normal, FontStyle.Italic),
    Font(R.font.ui_strong, FontWeight.SemiBold),
    Font(R.font.ui_strong_italic, FontWeight.SemiBold, FontStyle.Italic)
)

Text(text = "Title", fontFamily = UiFamily, fontWeight = FontWeight.SemiBold)
```

## Images

The build copies every image format and sorts the files by their indicator. See [Images]([[docsref:/asset-types/images#platform-output]]) for the source layout and the variants.

### Density folders

The build removes the indicator from the name and writes the file to the density folder that the indicator stands for, under the folder the image is in. An image without an indicator goes to `drawable/`.

<CxTable>
| Indicator | Folder |
| --- | --- |
| None | `drawable/` |
| `@1x` | `drawable-mdpi/` |
| `@1.5x` | `drawable-hdpi/` |
| `@2x` | `drawable-xhdpi/` |
| `@3x` | `drawable-xxhdpi/` |
| `@4x` | `drawable-xxxhdpi/` |
</CxTable>

The source files `images/hero-banner.png`, `hero-banner@2x.png` and `hero-banner@3x.png` of the app come out as one name in three folders:

```text
dist/android/<app>/<brand>/images/
├── drawable/
│   └── hero_banner.png
├── drawable-xhdpi/
│   └── hero_banner.png
└── drawable-xxhdpi/
    └── hero_banner.png
```

The build does not resize: an image has the variants that the designer exported, and no others. Android reads a file of `drawable/` as an mdpi image and scales it up on a denser screen. With `--res`, an image without any variant goes to `drawable-nodpi/` instead, so `R.drawable.wordmark` keeps its pixels: give it a size in the layout.

### Using an image

After the copy script ran, the three files are one resource, `R.drawable.hero_banner`, and Android picks the file of the screen density. Use it in a layout:

```xml
<ImageView
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:src="@drawable/hero_banner"
    android:contentDescription="@string/hero_banner" />
```

Use it in Jetpack Compose:

```kotlin
Image(
    painter = painterResource(R.drawable.hero_banner),
    contentDescription = stringResource(R.string.hero_banner)
)
```

### SVG images

The build copies an SVG image to `drawable/` as SVG, and `res/drawable/` does not accept that format, so the copy script leaves the SVG files out. Import the ones you need with Vector Asset Studio of Android Studio: **File → New → Vector Asset**, **Local file (SVG, PSD)**, then the file, for example `images/logo/drawable/wordmark.svg` of the job folder. Android Studio writes `res/drawable/wordmark.xml`.

An image that the designer exported as PNG and as SVG has both files with one name, such as `wordmark.png` and `wordmark.svg`. A resource has one file per folder, so use one of the two formats for a name, or give the vector drawable another name in the dialog.

### Night images

A build with `--res` joins a pair of one folder: `welcome_light.png` and `welcome_dark.png` of `images/onboarding/` are the resource `welcome`, with the dark files in the folders with the `night` qualifier. The density is kept:

```text
res/
├── drawable/welcome.png              # welcome_light.png
├── drawable-night/welcome.png        # welcome_dark.png
├── drawable-xhdpi/welcome.png        # welcome_light@2x.png
└── drawable-night-xhdpi/welcome.png  # welcome_dark@2x.png
```

The app reads `R.drawable.welcome` in both modes, and Android picks the file. An image of one size goes to `drawable-nodpi/` and `drawable-night-nodpi/`. Only a real pair is joined: `logo_light.png` alone keeps its name, and so do `logo_black.png` and `logo_white.png`.

The default output has no such rule: an image for a dark background is a file of its own with its own name. To let Android choose between the two, copy them to one resource name, the dark one into a folder with the `night` qualifier:

```bash
IMAGES="vendor/assets/dist/android/mobile/acme/images/onboarding"
RES="app/src/main/res"

mkdir -p "$RES/drawable-xhdpi" "$RES/drawable-night-xhdpi"
cp "$IMAGES/drawable-xhdpi/welcome_light.png" "$RES/drawable-xhdpi/welcome.png"
cp "$IMAGES/drawable-xhdpi/welcome_dark.png" "$RES/drawable-night-xhdpi/welcome.png"
```

## Icons

The build keeps only the SVG files under `icons/`. It adds the `ic_` prefix to a name that does not have it, and renames the files to snake_case. See [Icons]([[docsref:/asset-types/icons#platform-output]]) for where the icons come from.

```text
dist/android/<app>/<brand>/icons/
├── ic_arrow_right_outline.svg
├── ic_arrow_right_solid.svg
└── ...
```

### Vector drawables

An Android app draws an icon from a vector drawable. The build writes one for each icon when you give it the `--vector-drawables` option, which needs the package `svg2vectordrawable`:

```bash
cd vendor/assets
npm install svg2vectordrawable
npx chassis-assets build --platform android --vector-drawables
```

Each SVG file under `icons/` is then an XML file of the same name, which `res/drawable/` takes as it is:

```text
dist/android/<app>/<brand>/icons/
├── ic_arrow_right_outline.xml
├── ic_arrow_right_solid.xml
└── ...
```

A path without a fill color is filled black, which the tint of the app replaces. A file with no shape to draw stays an SVG, and the build warns about it. Add the icons to the copy script of [Copying to res](#copying-to-res):

```bash
# The vector drawables of the icons, from a build with --vector-drawables
mkdir -p "$SRC/res/drawable"
cp "$ASSETS"/icons/*.xml "$SRC/res/drawable/"
```

The release archives are built without the option and hold the SVG files. From an SVG file you make the vector drawable with Vector Asset Studio: **File → New → Vector Asset**, **Local file (SVG, PSD)**, then a file of `icons/`. Keep the name that the dialog proposes, so the resource has the name of the file: `ic_arrow_right_solid.svg` becomes `res/drawable/ic_arrow_right_solid.xml`. Import the icons the app uses, not the whole folder, and import an icon again when its SVG changes.

### Using an icon

A vector drawable is a drawable resource like an image, and takes its color from a tint. Use it in a layout:

```xml
<ImageView
    android:layout_width="24dp"
    android:layout_height="24dp"
    android:src="@drawable/ic_arrow_right_solid"
    android:contentDescription="@string/next"
    app:tint="?attr/colorOnSurface" />
```

Use it in Jetpack Compose:

```kotlin
Icon(
    painter = painterResource(R.drawable.ic_arrow_right_solid),
    contentDescription = stringResource(R.string.next),
    tint = MaterialTheme.colorScheme.onSurface
)
```

## App icon

The app icon is an adaptive icon, of a background, a foreground and a monochrome layer. The designer keeps the layers as SVG files in a bundle, a folder that ends in `.adaptive`, in a folder of its own:

```text
source/<brand>/<app>/app-icon/app-icon.adaptive/
├── background.svg
├── foreground.svg
└── monochrome.svg
```

Each layer is drawn on a square of 108 by 108 dp, with the mark inside the circle of 66 dp in its center, which is what every launcher shows of it. Android requires the background and the foreground, the launcher reads the alpha of the monochrome layer for a themed icon, and a brand replaces the bundle whole. The [app icons page]([[docsref:/asset-types/app-icons]]) has the rules of the layers and of the name.

A build with `--vector-drawables --res` writes the app icon:

```text
res/
├── drawable/
│   ├── app_icon_background.xml
│   ├── app_icon_foreground.xml
│   └── app_icon_monochrome.xml
└── mipmap-anydpi-v26/
    └── app_icon.xml
```

Name it in the manifest of the app:

```xml
<application android:icon="@mipmap/app_icon">
```

The name of the bundle is the name of the resource: a bundle `ic-launcher.adaptive` is `@mipmap/ic_launcher`, the name of a new project of Android Studio, with the drawables `ic_launcher_background`, `ic_launcher_foreground` and `ic_launcher_monochrome`. Android reads an adaptive icon from API 26 on, and the build does not resize, so an app that supports a lower API adds its own icon for those.

Without the options the bundle stays in `app-icon/app_icon.adaptive/`, with the SVG layers. With `--vector-drawables` alone the layers are vector drawables in the bundle, `background.xml`, `foreground.xml` and `monochrome.xml`, which you copy to `res/drawable/` under the names of the app icon XML above. With `--res` alone the bundle stays, and the build warns that it is no app icon without `--vector-drawables`.

## Other assets

The build copies any other folder of the app whole, with its subfolders, and renames its files to snake_case; a dot inside a name becomes an underscore too. A source file `data/brand.tokens.json` comes out as `dist/android/<app>/<brand>/data/brand_tokens.json`. A folder that only some brands hold is in the output of those brands only.

Copy such a file to `res/raw/` to read it as `R.raw.brand_tokens`, or copy the folder to `app/src/main/assets/` to keep its subfolders and read a file by its path. See [Other assets]([[docsref:/asset-types/other]]) for what the folder can hold.

## Brand switching

Every brand of `chassis.build.brands` has a job folder with the same folders, and a file that two brands both have has the same name in each, so an app changes brand by changing the folder it copies from. A brand file replaces the default file of the same path in the build; the names stay, and the code of the app does not change.

The brands do not have to hold the same files. A file that only the folder of one brand holds is in the output of that brand only, and a font role that a brand holds no files for has no files in its output. A resource that only some brands have, such as the font family resource of such a role, goes in the source set of each brand that has it. Compare the output of two brands to see which files they share:

```bash
diff <(cd vendor/assets/dist/android/mobile/acme && find . -type f | sort) \
     <(cd vendor/assets/dist/android/mobile/globex && find . -type f | sort)
```

### Product flavors

A product flavor per brand gives each brand its own source set, `app/src/<brand>/`, which is where the copy script writes. Name the flavors after the brands in `app/build.gradle.kts`:

```kotlin
android {
    flavorDimensions += "brand"

    productFlavors {
        create("acme") { dimension = "brand" }
        create("globex") { dimension = "brand" }
    }
}
```

`./gradlew assembleAcmeDebug` then builds the app with the files of `app/src/acme/`, and `./gradlew assembleGlobexDebug` with those of `app/src/globex/`. Put the vector drawables and the `ui.xml` that differ by brand in the same source sets, and the ones that all brands share in `app/src/main/res/`.

### Gradle task

A Gradle task runs the copy script before every build, so the source sets follow the output. Add one task per brand to `app/build.gradle.kts`:

```kotlin
listOf("acme", "globex").forEach { brand ->
    val sync = tasks.register<Exec>("sync${brand.replaceFirstChar { it.uppercase() }}Assets") {
        workingDir = rootDir
        commandLine("scripts/sync-assets.sh", brand)
    }

    tasks.named("preBuild") { dependsOn(sync) }
}
```

The task copies; it does not build the assets. Run `npx chassis-assets build --platform android` in `vendor/assets/` after a change to `source/` or after moving the submodule, or leave `npx chassis-assets build --watch --platform android` running there, which builds the Android jobs again on every change under `source/`.

An app that holds every brand in one APK and switches at run time cannot use the names as they are, since the brands share them: it needs a script that adds the brand to each name while copying.

## Continuous integration

A workflow builds the Android jobs, runs the copy script for each brand, then builds the app. The script and the Gradle tasks were run on a Mac with Gradle 9.8 and Android Gradle Plugin 9.4, with the build of the old repository; the build with the package and the workflow itself were not run. The build needs Node.js and the package, which `npm ci` installs in `vendor/assets/`. This workflow is for GitHub Actions, with the assets as a submodule:

```yaml
name: Android

on:
  push:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
        with:
          submodules: true

      - name: Fetch the Git LFS files of the assets
        run: git -C vendor/assets lfs pull

      - uses: actions/setup-node@v7
        with:
          node-version-file: vendor/assets/.nvmrc

      - name: Build the Android assets
        working-directory: vendor/assets
        run: |
          npm ci
          npx chassis-assets build --platform android

      - name: Copy the assets
        run: |
          ./scripts/sync-assets.sh acme
          ./scripts/sync-assets.sh globex

      - uses: actions/setup-java@v6
        with:
          distribution: temurin
          java-version: 17

      - name: Build the app
        run: ./gradlew assemble
```

With release archives the workflow needs neither the submodule nor Node.js: it downloads the archive of each brand, unpacks it as in [Release archive](#release-archive), and runs the copy script with `ASSETS_ROOT`.

## Best practices

These practices keep the copy from `dist/android/` into `res/` repeatable, so every file of the app comes from a build of the assets.

- **Copy by a script:** keep the list of the `images/` folders the app uses in `scripts/sync-assets.sh`, so a new file of `source/` reaches `res/` with the next build.
- **Keep the licenses:** ship the `<role>_license.txt` files of `fonts/` with the app, from `assets/licenses/`.
- **Name flavors after brands:** a flavor named as the brand in `chassis.build.brands` maps `dist/android/<app>/<brand>/` to `app/src/<brand>/` without a table of names.
- **Ask for the variants:** the build does not resize, so an image that has only a `drawable/` file needs `@2x` and `@3x` exports in `source/`.
- **Pin the assets:** use a submodule commit or the archive of one version, so a build of the app is repeatable.
- **Build with `--webp` for smaller images:** the option, which needs the package `sharp`, writes a lossless WebP in place of each PNG that it makes smaller, under the same resource name.

Avoid the habits that undo this:

- **Do not edit the copies:** a file under `app/src/<brand>/res/` that the script wrote is replaced by the next run. Change the file in `source/` and build again.
- **Do not rename in the app:** the names of `dist/android/` are the same for every brand. A renamed copy breaks that for the next brand.
- **Do not keep one image as PNG and as WebP in `res/`:** the Android output has both when the designer exported both, and a resource has one file per folder. Remove the extension the app does not use from the copy script.
- **Do not commit `dist/`:** it is build output. Commit the submodule pointer, or name the version of the archive.

## Troubleshooting

Each entry gives the message or the symptom, then the cause and the fix.

### Git LFS pointers

The build stops with `<count> source file(s) are Git LFS pointers, not files`, followed by the first of them. The clone or the submodule was made without Git LFS, so the fonts and the raster images are text files of a few lines. Install Git LFS, run `git lfs pull` in `vendor/assets/`, and build again.

### Unknown brand

The build stops with `Unknown brand "<name>". Configured: <brands>`. The value of `--brand` is not in `chassis.build.brands` of `package.json`; `--app` and `--platform` fail the same way. Use a configured name, or add the brand to the configuration.

### Copy script fails

The copy script stops at a `cp` line with `No such file or directory`. The job folder is missing, because the Android build did not run or `ASSETS_ROOT` points elsewhere, or the brand has no file of that extension in `fonts/`. Run `npx chassis-assets build --platform android`, check the path, and remove the pattern that matches nothing from the script.

### SVG file in res

Gradle fails on a file of `res/drawable/` with `The file name must end with .xml or .png`. An SVG of `images/` or `icons/` was copied as it is, and `res/` does not accept SVG. Remove the file and import it with Vector Asset Studio, as in [SVG images](#svg-images), or build the icons with `--vector-drawables`, as in [Vector drawables](#vector-drawables).

### Duplicate resources

Gradle fails with `Duplicate resources` and names two files of one folder, such as `wordmark.png` and `wordmark.xml`. The image exists as PNG and as SVG in `images/logo/`, and both were added to `res/drawable/`. Keep one of them, or import the SVG under another name. The two files can also be a copy of an earlier build and one of this build: `wordmark.png` is still in `app/src/chassis/res/drawable/` when a build with `--webp` writes `wordmark.webp` in its place. Delete the file of the earlier build.

### Image is missing

An image of `source/` is not where you look for it in the job folder. An image with an indicator is in a density folder under the subfolder of the image, not in `drawable/`, and its name is in snake_case without the indicator. Search for the name with `find dist/android/mobile/acme/images -name '<name>*'`.

### Image looks blurry

An image is soft on a dense screen. It has only a file in `drawable/`, which Android scales up. Add the `@2x` and `@3x` variants to `source/`, build, and run the copy script, or build with `--res`, which writes an image of one size to `drawable-nodpi/`.

### Two files ask for a resource

The build stops with `Two files ask for the resource drawable/<name>`, followed by the files. A pair `<name>_light` and `<name>_dark` and another image `<name>` would be one resource in a build with `--res`. Rename one of them in `source/`.

### Icon is not found

The compiler reports `Unresolved reference` for an icon such as `R.drawable.ic_arrow_right`. The name of an icon ends with its style, and the vector drawable exists only after the copy or the import: check the name with `ls dist/android/mobile/acme/icons`, and use `ic_arrow_right_solid` or `ic_arrow_right_outline`.
