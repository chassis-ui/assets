## Introduction

Icons are the files under `icons/` of an app. They are not drawn or exported here: the folder holds a copy of the build output of [Chassis Icons](https://chassis-ui.com/icons), which the build then copies to each platform.

The web output gets every file of the folder. iOS gets the SVG, PDF and PNG files, and Android gets the SVG files, each with the `ic_` prefix. The build copies an icon as it is. With the `--vector-drawables` option it writes the SVG icons of Android as vector drawables.

## Source layout

Icons live in `source/<brand>/<app>/icons/`, in the two folders that Chassis Icons writes: `icons/` for the icon font, its stylesheets and the sprite, and `svgs/` for one SVG file per icon.

```text
source/default/demo/icons/
├── icons/
│   ├── chassis-icons.css
│   ├── chassis-icons.json
│   ├── chassis-icons.min.css
│   ├── chassis-icons.scss
│   ├── chassis-icons.svg          -> the sprite of every icon
│   ├── chassis-icons.woff
│   └── chassis-icons.woff2
└── svgs/
    ├── arrow-right-outline.svg
    ├── arrow-right-solid.svg
    └── ...
```

In this repository only the `demo` app of the default brand holds a copy of Chassis Icons. The `docs` app holds `source/default/docs/icons/cx-sprite.svg` only, a sprite of this repository and not of Chassis Icons, which the build copies like any other file of `icons/`.

A brand with icons of its own has the same two folders under `source/<brand>/<app>/icons/`. A brand file replaces the default file of the same path, so a brand may also replace single icons under `svgs/` and take the rest from the default brand.

## Formats

Each platform keeps the formats it can use, and the build leaves the rest out.

<CxTable>
| Format | Web | iOS | Android |
| --- | --- | --- | --- |
| SVG | Copied | Copied | Copied |
| PDF, PNG | Copied | Copied | Dropped |
| WOFF, WOFF2, CSS, SCSS, JSON | Copied | Dropped | Dropped |
</CxTable>

The icon font and its stylesheets are for the web, so the apps get the SVG files only. An Android app draws an icon from a vector drawable: a build with `--vector-drawables` writes one per SVG file, and Vector Asset Studio of Android Studio makes one from a single file.

## Naming

An icon is named after what it shows, followed by its style: `arrow-right-solid.svg`, `arrow-right-outline.svg`. The names are those of Chassis Icons, and a brand with icons of its own keeps them, so that an app refers to `arrow-right-solid` whichever brand it is built for.

The build renames each file for the platform. On Android it also adds the `ic_` prefix to every file under `icons/`, unless the name starts with it already.

## Adding files

The files of `icons/icons/` and `icons/svgs/` are the build output of another project. Change an icon in Chassis Icons, build it there, and copy the output here.

<Callout type="warning">
Do not edit a file under `icons/icons/` or `icons/svgs/` by hand. The next copy from Chassis Icons replaces it.
</Callout>

### Refreshing the copy

The `demo` app of the default brand of this repository holds the icons of the `@chassis-ui/icons` package, which ships the two folders as they are. Install the dependencies, replace the folders of the app with those of the package, and build:

```bash
pnpm install
rm -rf source/default/demo/icons/icons source/default/demo/icons/svgs
cp -r packages/site/node_modules/@chassis-ui/icons/icons source/default/demo/icons/icons
cp -r packages/site/node_modules/@chassis-ui/icons/svgs source/default/demo/icons/svgs
pnpm assets
```

The icon font files are Git LFS files, so make the commit on a machine with Git LFS. Compare `dist/` before and after: an icon that was under `icons/svgs/` and is gone breaks an app that reads it by name.

### Brand icons

A brand with another icon style builds its own set with Chassis Icons, under the same icon names, and copies the output to `source/<brand>/<app>/icons/`. The [Chassis Icons docs](https://chassis-ui.com/icons) describe how a set is drawn and built.

## Integration

Chassis Icons owns the icons: the drawings, the icon font, the sprite and the class names of the stylesheets. Chassis Assets stores a copy of its output per brand and app, and gives each platform the files it can use under the names it expects.

The [Chassis Icons docs](https://chassis-ui.com/icons) show every icon with its name and describe how a page uses the font and the sprite.

## Best practices

The icon files are a copy of the output of Chassis Icons. These practices keep the copy whole and the icon names stable across brands.

- **Keep the icon names across brands:** an app that shows `arrow-right-solid` gets the drawing of the brand it is built for. A brand that renames an icon needs a change in every app.
- **Refresh both folders together:** `icons/icons/` and `icons/svgs/` come from one build of Chassis Icons. A font from one version and SVG files from another disagree on the icons they hold.
- **Refresh every app that holds a copy:** each app has a copy of its own. In this repository only `demo` of the default brand holds one.

Avoid the habits that undo this:

- **Do not put other images under `icons/`:** Android adds the `ic_` prefix to every file of the folder, and the apps get only the formats of the table above. A logo or an illustration belongs under `images/`.

## Platform output

The build copies each file to the `icons/` folder of the job, in its subfolder, and renames it for the platform.

<CxTable>
| Platform | Folder | Name | Formats |
| --- | --- | --- | --- |
| Web | `dist/web/<app>/<brand>/icons/` | kebab-case | Every format |
| iOS | `dist/ios/<app>/<brand>/icons/` | snake_case | SVG, PDF, PNG |
| Android | `dist/android/<app>/<brand>/icons/` | snake_case with the `ic_` prefix | SVG |
</CxTable>

The web output keeps every file. The configured web app holds no copy of Chassis Icons, so its output holds the sprite of this repository only:

```text
dist/web/docs/chassis/icons/
└── cx-sprite.svg
```

A web app that holds a copy gets both folders under `icons/`, with the dot inside a name made a hyphen: `chassis-icons.min.css` is `icons/icons/chassis-icons-min.css`.

The iOS output of the configured app holds the sprite and the SVG file of each icon:

```text
dist/ios/demo/chassis/icons/
├── icons/
│   └── chassis_icons.svg
└── svgs/
    ├── arrow_right_outline.svg
    ├── arrow_right_solid.svg
    └── ...
```

The Android output holds the same files with the prefix:

```text
dist/android/demo/chassis/icons/
├── icons/
│   └── ic_chassis_icons.svg
└── svgs/
    ├── ic_arrow_right_outline.svg
    ├── ic_arrow_right_solid.svg
    └── ...
```

A build with `pnpm assets --vector-drawables` writes each of these SVG files as a vector drawable of the same name. The SVG file of the icon font has no shape to draw, so it stays, and the build warns about it:

```text
dist/android/demo/chassis/icons/
├── icons/
│   └── ic_chassis_icons.svg
└── svgs/
    ├── ic_arrow_right_outline.xml
    ├── ic_arrow_right_solid.xml
    └── ...
```

See the [web]([[docsref:/use-in-project/web-applications#icons]]), [iOS]([[docsref:/use-in-project/ios-applications#icons]]), and [Android]([[docsref:/use-in-project/android-applications#icons]]) docs for how an app uses these files.
