## Introduction

Images are the files under `images/` of an app: logos, illustrations, photos, screenshots and backgrounds. The build copies them to every platform with the name the platform expects, and keeps the subfolders of `images/`.

An image has the variants the designer exported. The build does not resize or re-encode a file. It reads the `@2x` or `@3x` indicator of a name, and on Android it sorts the variants into density folders.

## Source layout

Images live in `source/<brand>/<app>/images/`, in any subfolders. The default brand holds the images of every brand, and a brand holds only the files that differ.

```text
source/default/demo/images/
├── chassis-logo.svg
├── chassis-logo-shadow.png
├── chassis-logo-shadow@2x.png
├── home/
│   ├── comp-gallery-dark.png
│   ├── comp-gallery-dark@2x.png
│   └── ...
└── logo/
    └── ...
```

A brand file replaces the default file of the same path, subfolder included. The example brand of this repository has a `logo/` folder only, so it gets its own logos and every other image of the default brand.

## Formats

The build copies an image of any format. One format is the exception: iOS and Android do not get WebP files.

<CxTable>
| Format | Web | iOS | Android |
| --- | --- | --- | --- |
| PNG, JPG, GIF, SVG | Copied | Copied | Copied |
| WebP | Copied | Dropped | Dropped |
</CxTable>

Export a WebP image in a second format, PNG or JPG, when an app needs it too. The web output then holds both files, and a page chooses between them with a `<picture>` element.

PNG, JPG and WebP files are Git LFS files. SVG files are text and are committed as they are.

## Naming

Name an image in lowercase with hyphens, after what it shows: `comp-gallery-dark.png`, `chassis-logo-white.svg`. Each platform renames the file, so the source name is written once and the web, iOS and Android names follow from it.

### Variants

A variant is the same image exported at another resolution. Its name ends with an indicator before the extension: `@2x` for twice the size, `@3x` for three times. The file without an indicator is the base size.

```text
source/default/demo/images/logo/
├── chassis-icon-black.png
├── chassis-icon-black@2x.png
└── chassis-icon-black@3x.png
```

The web and the iOS output keep the indicator in the name. Android has no indicator: the build writes each variant under the same name into the density folder of its resolution, see [Platform output](#platform-output).

### Color modes

An image that differs between the light and the dark mode is two files, with the mode at the end of the name: `comp-gallery-light.png` and `comp-gallery-dark.png`. The build treats them as two images, and the app chooses between them.

## Adding files

An image enters the repository as an export from the design tool, saved under `images/` of the brand and the app it belongs to.

1. Name the layer or the frame in the design tool as the file is to be named, without the extension.
2. Add one export setting per variant: the base size, then `2x` and `3x` for a raster image that an app shows. Figma adds the `@2x` and `@3x` indicators to the names by itself. An SVG needs no variant.
3. Export to `source/default/<app>/images/` for an image of every brand, or to `source/<brand>/<app>/images/` for an image of one brand.
4. Run `pnpm assets` and look for the file in `dist/`.

A subfolder groups images that belong together, such as `logo/` or `home/`. The build keeps the subfolder on every platform.

## Best practices

✅ **Export every variant an app needs:** the build copies `@2x` and `@3x` files and does not make them. An image without variants reaches Android in `drawable/` only.

✅ **Keep the base name the same across variants:** `hero.png`, `hero@2x.png` and `hero@3x.png` become one Android drawable in three densities. A variant with another base name becomes another image.

✅ **Add a PNG or JPG beside a WebP:** iOS and Android do not get WebP files.

✅ **Override by path:** a brand image replaces the default image only when the subfolder and the name are the same, `images/logo/chassis-logo.svg` for `images/logo/chassis-logo.svg`.

❌ **Do not put icons of the interface under `images/`:** the files of `icons/` come from Chassis Icons, and Android gives them the `ic_` prefix. See [icons]([[docsref:/asset-types/icons]]).

## Platform output

The build copies each image to the `images/` folder of the job, in its subfolder, and renames it for the platform.

<CxTable>
| Platform | Folder | Name | Formats |
| --- | --- | --- | --- |
| Web | `dist/web/<app>/<brand>/images/` | kebab-case, indicator kept | Every format |
| iOS | `dist/ios/<app>/<brand>/images/` | snake_case, indicator kept | Every format but WebP |
| Android | `dist/android/<app>/<brand>/images/` | snake_case, in density folders | Every format but WebP |
</CxTable>

The source file `images/home/comp-gallery-dark@2x.png` is `images/home/comp-gallery-dark@2x.png` in the web output and `images/home/comp_gallery_dark@2x.png` in the iOS output. In the Android output it is `images/home/drawable-xhdpi/comp_gallery_dark.png`:

```text
dist/android/demo/chassis/images/
├── drawable/
│   ├── chassis_logo.svg
│   ├── chassis_logo_shadow.png
│   └── ...
├── drawable-xhdpi/
│   └── chassis_logo_shadow.png
├── home/
│   ├── drawable/
│   │   ├── comp_gallery_dark.png
│   │   └── ...
│   └── drawable-xhdpi/
│       ├── comp_gallery_dark.png
│       └── ...
└── logo/
    ├── drawable/
    ├── drawable-xhdpi/
    └── drawable-xxhdpi/
```

On Android the indicator of a name chooses the density folder, and a file without an indicator goes to `drawable/`.

<CxTable>
| Indicator | Density folder |
| --- | --- |
| none | `drawable/` |
| `@1x` | `drawable-mdpi/` |
| `@1.5x` | `drawable-hdpi/` |
| `@2x` | `drawable-xhdpi/` |
| `@3x` | `drawable-xxhdpi/` |
| `@4x` | `drawable-xxxhdpi/` |
</CxTable>

The density folders are written inside each subfolder of `images/`, so `images/logo/` has density folders of its own. The `res/` folder of an Android app does not nest, so an app copies the density folders of each subfolder it uses into `res/`.

See the [web]([[docsref:/use-in-project/web-applications#images]]), [iOS]([[docsref:/use-in-project/ios-applications#images]]), and [Android]([[docsref:/use-in-project/android-applications#images]]) docs for how an app uses these files.
